# 小程序采购中心升级

## 范围

本次完成第一阶段的小程序“我的”及相关子页面升级。未修改生产环境、未发布新体验版，未创建订单或重置数据库。

- 门店名称、联系人脱敏手机号、审核状态与真实客户等级。
- 待确认、待发货、待收货全量统计，以及原生订单 Tab 筛选联动。
- 订单列表新增分页，进行中筛选由服务端执行。
- 账期概览默认隐藏金额；有授信额度或已用额度才展示。详情不将已用额度解释为逾期欠款。
- 最近两笔已完成采购，支持查看原订单与再次采购。
- 再次采购按实时校验价格、库存与起订量加入购物车，保留原购物车，兼容不同品牌分单结算。
- 协议价格按商品或规格搜索，点击进入对应商品并选择对应 SKU。
- 完整收货信息复制，包括门店、联系人、电话与地址。
- 独立账户设置、协议、隐私政策、真实版本信息与确认退出。
- 常见采购问题、微信原生意见反馈、可配置客服电话。

## 接口

`GET /api/v1/orders/me/overview` 需要登录，订单访问守卫解析当前客户及租户，不接受查询参数覆盖身份。无关联客户的管理账号不能通过此接口获得租户总览。

返回 `counts`（按状态聚合）和 `recentOrders`（最近两笔已完成订单摘要）。统计使用数据库 `groupBy`，不依赖订单列表页大小。

`GET /api/v1/auth/profile` 新增 `customer.customerLevelName` 与 `support`。只返回启用的客户等级名称，不向小程序暴露等级内部模型。

未增加数据库表或迁移。

## 客服配置

在后端部署环境设置以下值并重启服务：

```dotenv
SUPPORT_PHONE=
SUPPORT_HOURS=
```

必须由运营确认实际号码、服务时间后填写。未配置时不显示拨号按钮，不从管理员手机号自动推导客服电话。原生“意见反馈”由微信平台承接，不是订单售后工单或即时客服。

## 验证

```powershell
node --test tests/*.test.js
npm --prefix backend run typecheck
npm --prefix backend test -- --silent
node scripts/prepare-local-mini.cjs
# 在微信开发者工具打开生成的本地联调项目，并启用自动化端口 9421。
node scripts/verify-profile-center.cjs
```

模拟器脚本复用本地客户登录，验证三种订单筛选、企业资料、地址、账期、协议价格搜索、设置与帮助。截图保存在桌面的 `唯多鲜-界面验证/profile-upgrade`。不会下单、付款、修改客户资料或拨打电话。

自动化覆盖：客户/租户隔离、未登录拒绝、统计不受分页影响、真实等级、额度零值、断网状态、筛选竞态、再次采购价格/库存/起订量，以及字符串与数字 SKU 合并。

## 发布与后续

- 发布时先部署后端，再上传原始项目的小程序包；不要上传 `.wx-local-project`。
- 线上网站和现有 1.1.0 体验版未因本次本地修改自动更新。
- 多地址及受控修改、对账还款明细、发票、售后工单与通知中心留在第二阶段。
- 微信原生意见反馈与拨号需在真机、真实服务配置下最终验收；协议正文仍需上线前审阅。
