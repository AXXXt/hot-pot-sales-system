# 协议版本、同意记录与公开咨询

更新：2026-10-24。此文说明本轮源码实现及验证边界，不代表微信正式发布或最终法律文本已经确认。

## 共享文案与待确认事实

`constants/legal.json` 是小程序、后台、采购站、官网和后端的共享来源。运行 `node scripts/sync-legal.cjs` 会生成小程序CommonJS、后端TypeScript和官网浏览器脚本。后端以 `SHA256(JSON.stringify(共享对象))` 记录本次呈现文档摘要；修改正文或准备状态时必须更新版本，避免同一版本对应不同内容。应保存已发布版本的源码，不用新正文覆盖历史记录的摘要。

本轮负责人确认经营主体“河南唯哆鲜食品有限公司”、联系“13937802005”和腾讯云服务器。当前版本 `2026-10-24-draft-1` 仍明确为审阅稿；实际存储地区、各类资料保存期限、退换货具体规则和微信平台隐私指引实际核对尚未完成。不得仅因为程序可以留痕就改称正式版本或完成合规验收。

## 账号同意

短信登录、注册/重提、后台密码登录提交 `consentAccepted=true`、当前 `consentVersion` 及渠道 `mini/buyer_web/admin_web`。前端勾选默认关闭，不在API封装里自动构造“已同意”。服务端在消耗验证码/校验密码前检查明确同意和版本；缺失、拒绝、错误渠道或旧版本均拒绝。静默刷新不补造同意、不重复弹窗，也不将历史登录反推为同意。

身份核验成功后记录 `legal_consents`：可信用户及租户ID、版本、文档摘要、渠道和数据库生成的首次同意时间。每用户/版本/渠道保留首条记录，不因再次登录改写原时间。新客户创建与同意记录在同一事务；记录失败不应留下半个新账号。表中不额外保存手机号、客户端声称的时间或客户端声称的文档哈希。

`GET /api/v1/legal/current` 可公开阅读当前版本；`GET /api/v1/legal/consent` 只能读取当前认证账号的当前版本同意状态；`POST /api/v1/legal/consent` 供已登录用户主动补确认。该补确认也必须明确勾选且不接受客户端指定其他用户ID。保留旧会话期间不会批量回填历史用户的同意记录；用户下次主动登录或主动补确认时才留痕。

## 官网咨询与重试

官网展示用户协议、隐私政策及明确的“回复本次咨询”选择，未勾选不发送表单。后端也校验同意，不能通过直接调用绕过。创建线索与其同意记录同事务提交，失败整笔回滚；蜜罐仍先静默丢弃，不制造线索。

表单生成UUID requestId，相同内容在丢失响应后重试沿用原值，内容变化重新生成。后端在`lead_submissions`保存每个成功nonce的SHA256提交键、规范化内容摘要和关联线索；同键同内容返回原成功，避免重复线索和重复同意，不再次计数；同键不同内容返回409。不同nonce的相同规范化咨询内容在5分钟内也合并：短事务锁定租户行后按手机号、摘要和创建时间复查，避免并发创建两条；合并的nonce也在同事务保存别名，超出5分钟重放仍指向原成功。新nonce尝试仍计入原小时频次，不把去重当作无限提交权限；不同内容和超出5分钟的新nonce可以新建。该公开入口按租户串行短事务，不在该锁内访问外部短信或微信服务。

## 线索关联转化

后台“关联转化”必须选择已开户、启用、同租户且在当前工作人员客户范围内的客户。只保存线索与客户的关联，不创建用户、签发令牌或跳过短信与客户审核。状态变化、关联变化和审计在行锁保护的同一事务提交；失败回滚。离开“已转化”状态时移除当前关联，历史审计保留原客户编号。原先仅有converted状态而没有关联的旧记录不会自动猜测匹配客户。

## 微信平台隐私

业务协议勾选与微信平台隐私授权分别处理。选择付款图片前，在支持的基础库调用 `wx.requirePrivacyAuthorize`；拒绝或接口失败不进入选图、上传和提交。旧基础库没有该接口时保留原生选图权限流程。协议页提供 `wx.openPrivacyContract` 入口，失败显示可读提示。

没有通过自定义 `onNeedPrivacyAuthorization` 替用户同意，也没有把业务checkbox当作微信平台已授权。微信公众平台的隐私指引、实际接口声明、主体信息及体验/正式包效果仍须在公众平台和设备核对，单元回调不能替代平台验收。
