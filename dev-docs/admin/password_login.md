# 管理端账号密码登录

管理端支持“密码登录”和原有“验证码登录”。账号沿用已有后台人员的手机号，不会新建、提权或合并用户。小程序及客户采购站继续使用原登录方式。

## 设置和修改

- 超级管理员在用户管理点击“设置密码链接”，将链接交给该后台人员。链接15分钟有效、只能使用一次；重新生成后旧链接失效。
- 对方自行打开链接，设置15～128字符密码；支持长句和Unicode，区分大小写，不裁剪或截断密码。
- 已配置密码的人员可从后台右上角“修改密码”验证旧密码并修改；忘记密码时由超级管理员重新生成设置链接。
- 没有初始化过密码的人员不能用空密码、手机号或验证码代替密码登录。
- 密码初次设置、重设或修改后，旧访问令牌、刷新令牌以及依赖旧权限指纹的业务草稿/发布确认失效。
- 初始超级管理员因短信不可达而无法登录时，通过受控服务器运维通道调用同一密码链接服务，为既有账号签发链接。禁止在脚本、文档或聊天中设定固定初始密码。

## 数据和安全边界

新增迁移 `20261022050000_staff_password_login`，只创建 `staff_credentials` 表及用户外键，不修改商品、库存、订单或原账号字段。密码哈希与用户资料分表，普通用户查询不会带出哈希。

哈希使用Node内置scrypt：N=32768、r=8、p=3，16字节随机盐、64字节派生值及常量时间比较。每账号15分钟最多5次密码尝试，成功后清除该账号计数；每IP15分钟最多30次。Redis不可用时拒绝密码登录及密码设置，不回退无限次尝试。

后台密码入口仅接受有效租户的有效后台人员，客户账号不能使用。密码设置链接只由当前租户的有效超级管理员生成。链接令牌仅以摘要保存在Redis，URL使用fragment避免进入服务器请求日志。审计只记录操作类型和账号ID，不记录密码、哈希或链接令牌。

JWT增加凭据版本cv；未设置密码的原账号版本为0，保持旧会话兼容。改密后版本递增，业务鉴权、刷新令牌和独立版本控制服务均核对该版本；业务权限指纹也绑定已配置的凭据版本。

生产后端按1跳可信Nginx代理获取真实客户端IP。后端无宿主机公开端口，Nginx覆盖客户端转发头；不要另行暴露后端端口。

## 验证与发布

- 后端单元/合同测试覆盖密码哈希、旧会话失效及原短信登录兼容。
- 独立MySQL `_test` 库和带随机前缀的Redis集成覆盖真实HTTP、权限、一次性/过期链接、并发确认、错误次数限制、改密及令牌撤销。
- 浏览器覆盖密码默认入口、短信切换、错误提示、设置确认、过期链接、正常跳转和375px布局。
- 生产只读验证路由、权限和界面；正式账号的最终密码由本人填写。禁止向正式商品、库存或订单写测试数据。

该版本跨18到19项迁移，使用受信任root发布脚本 `deploy/release-staff-password.py`：核对镜像、资源及旧迁移校验和，完整备份，暂停业务后端，应用增量迁移，部署业务及独立控制镜像，核对12类原业务表摘要和原环境配置，登记版本及审计。此前不支持凭据版本的旧应用不开放直接回滚。

密码哈希参数依据：[OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。
