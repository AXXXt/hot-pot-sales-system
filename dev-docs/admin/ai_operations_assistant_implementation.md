# AI 运营助手首版实施记录

版本：1.0｜更新日期：2026-10-21｜作者：Codex

对应[设计基线](./ai_operations_assistant_design.md)。已完成本地代码、数据库接入、用户提供的 DeepSeek API 真实联调，并于 2026-10-21 部署生产环境。当前平台 `v1.2.0 / ai-20261021-3`，支持品牌、分类组合创建及图片拖放，详见[生产发布及回滚记录](../production_deployment.md)和[版本管理说明](./platform_release_control.md)。

## 1. 已交付能力

### 1.1 第一步：基础改造

- `StaffAccessService` 从数据库读取有效账号、租户、角色、权限、品牌及销售负责的客户和线索范围。
- AI 路由没有声明权限时直接拒绝；每次请求校验当前权限，业务工具执行前再次读取身份。
- 工作台统计与 AI 统计都加入调用者范围；工作台未授权模块隐藏，避免以 0 冒充真实数据。
- 统一以北京时间解释日期，明确“有效订单金额”不等同于实收或利润。
- 商品与首批 SKU 在同一数据库事务中创建，默认下架、初始库存为 0。
- 草稿确认绑定用户、范围指纹、版本、摘要、10 分钟有效期。并发及重复确认只返回同一执行记录。
- 正式业务写入、执行记录与必要审计同成同败；事务失败可安全重试。
- 原规格编辑禁止直接改库存；库存统一通过出入库单调整。修改已有 SKU 售价增加 `product:price:update` 校验。
- 识别照片使用独立私有桶 `<MINIO_BUCKET>-ai-private`，不继承商品图桶的公开策略。
- 识别图片校验真实格式，限制文件/像素大小，纠正方向并清除 EXIF；附件只允许上传人访问，7 天后清理。
- API Key 采用 AES-256-GCM 加密，服务地址使用批准域名白名单并禁止跳转。
- 新增数据库迁移 `20261021090000_ai_operations_assistant`，注册权限，默认只向超级管理员角色授予新权限。

### 1.2 第二步：悬浮助手首版

- 全局悬浮入口，可最小化、拖动、还原位置和展开工作区；切换路由保持当前会话。
- 小屏全屏交互，锁定背景滚动并支持键盘焦点约束；窗口位置信息按账号保存，不在本地存业务对话。
- 支持文字、上传、粘贴及直接拖入包装照片，每次最多 3 张、单张最多 5MB；整个悬浮窗支持拖放提示，附图与未发送文字跨页面保留。
- 会话展示服务器阶段事件、错误、结果卡片及可编辑草稿，确认由独立按钮触发。
- 文本与视觉采用标准工具调用协议。模型只能申请白名单工具，不持有登录令牌和数据库权限。
- 可以查询今日待办、订单、商品、客户、库存、个人事务和确定性统计。
- 可以生成商品及个人提醒草稿，补充字段后保存、检查并确认。
- 商品草稿支持待新建品牌及分类名称，自动复用已授权同名项；确认一次，在一个事务里创建必要的品牌、分类、商品和 SKU。
- 草稿内可切换已有项和新建名称；原来缺品牌、分类的草稿可以直接补齐并保存，不丢失规格。
- 对旧照片草稿继续询问品牌、分类或规格时，会重新鉴权并使用原私有附件识别。
- 引用订单/商品页面时，只把经服务端重新鉴权的最小信息交给模型。
- 单个会话限制并发；生成失败不会自动执行正式业务命令。
- 历史业务结果不作为长期可见缓存，重新打开时要求重新查询；范围变化后封存旧会话。
- 退出登录清空窗口中的业务状态与图片预览。

### 1.3 第三步：运营增强

- 文字清单可一次生成最多 10 个独立商品草稿，每项分别检查确认。
- 商品资料检查可查缺主图与缺规格，提供编辑入口。
- 报价辅助读取授权订单的历史价并标明时间，正式报价仍在原订单页完成。
- 补货建议按授权范围内最近 14 天下单且已发货/完成的同单位数量估算 7 天需求；不自动采购或入库。
- 经营统计支持当天、本周、本月，显示时间、口径、上一相同已过时段及商品排名。
- Excel 导出使用同一授权统计查询，并需要独立导出权限。
- 个人事务支持明确的北京时间提醒与完成操作；页面打开时每分钟刷新到期数量。
- BullMQ 通过现有 Redis 调度每日待办和每周一报告；周报统计上一完整周。
- 自动任务运行时重查账号和范围，权限变化后暂停。报告打开时按当前权限刷新结果。

## 2. 配置入口

本地管理台：[AI 助手配置](http://127.0.0.1:5173/ai-settings)。使用已有管理员账号登录。

生产管理台：[AI 助手配置](https://admin.weiduoxian.cn/ai-settings)。已为已有管理员租户加密配置并启用文字和拍照建品、统计及个人事务；普通角色需另行分配权限。生产使用独立加密主密钥，未复制开发环境密钥或开发业务数据。

左侧只有一个“AI 助手配置”菜单，页面包含六个标签：模型连接、能力与权限、业务规则、知识与模板、自动任务、用量与审计。

### 2.1 启用模型

1. 填写批准的供应商 API 服务地址，以及账户实际可用的文本模型。
2. 如需要拍照建品，填写同一服务下支持图片理解与工具调用的视觉模型。
3. 填写供应商 API Key，保存后浏览器只显示“已保存密钥”，不回显明文。
4. 打开启用开关并保存，使用“测试已保存的文本连接”。
5. 用代表性包装照片验证视觉效果；连接测试只证明文本接口可达，不等同于图片和工具能力验收。
6. 如需创建商品或提醒，再开启“允许确认后执行业务操作”。

本地已初始化独立的 `AI_ENCRYPTION_KEY`，没有打印或提交其值。用户提供 API 后，已为本地管理员租户加密保存配置并启用：服务地址 `https://api.deepseek.com/v1`，文本及视觉模型均为 `deepseek-flash`，每人每日上限 100 次。允许确认后创建商品和个人提醒；模型回复和聊天中的“确认”不会触发正式写入。

按 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)，当前接口默认开启思考模式。本实现明确关闭该模式，避免依赖供应商推理记录；后续请求使用业务对话、已鉴权页面信息和草稿上下文。此适配只对 DeepSeek 域名发送，其他供应商不携带该参数。图片输入使用[官方视觉接口格式](https://api-docs.deepseek.com/guides/vision/)，并已实际调用验证。

生产启用前应为目标环境生成独立的 32 字节 Base64 主密钥，以 `AI_ENCRYPTION_KEY` 注入后端。新增部署环境的 `deploy/init-env.sh` 会生成该值；已有生产环境不会被脚本覆盖，应通过现有秘密配置流程补充。

当前文本与视觉共用一个服务地址和一个 API Key；尚未实现跨供应商的文本/视觉密钥组合。

### 2.2 分配权限

| 需要的能力 | 必须满足 |
| --- | --- |
| 显示助手 | `ai:use`，且账号有效 |
| 一句话/拍照建品 | `ai:use`、`product:create`、允许操作的品牌 |
| 确认建品 | 上述权限 + `ai:execute`，配置允许写入 |
| 随商品新建品牌 | 确认建品权限 + `brand:manage` |
| 随商品新建分类 | 确认建品权限 + `product:update`，与原分类管理入口一致 |
| 查看订单 | `ai:use`、`order:read`，且订单在用户范围内 |
| 经营统计 | `ai:use`、`analytics:view`、`order:read` |
| 库存查询 | `ai:use`、`inventory:read`，且品牌在范围内 |
| 个人事务 | `ai:use`、`task:manage_own`；确认草稿还需要 `ai:execute` |
| 修改配置 | `ai:configure` |
| 配置角色能力与人员品牌范围 | `ai:configure` + `role:manage`，不能授予超出自己范围的能力或品牌 |
| 修改已有 SKU 售价 | `product:update` + `product:price:update` |
| 统计导出 | 统计权限 + `export:create` |

“能力与权限”标签可以按角色分配已获授权的能力，并设置人员品牌范围。普通人员没有品牌授权时默认不能查询品牌业务；销售的客户、线索和订单还受负责范围限制。

新能力不自动开放给普通角色。配置管理员不因此得到业务数据权限。超级管理员沿用现有业务特例，但也不能越过租户、工具开关、草稿确认及业务状态约束。

新品牌创建者获得该新品牌的范围，不会自动获得其他已有品牌；这次范围增加会封存旧范围会话，客户端在成功后刷新字典并开始新会话。已完成组合操作可在当前仍有业务权限和商品范围时安全重试确认。品牌创建、创建者范围、分类、商品、SKU 和必要审计同成同败，失败全部回滚。

## 5. 当前边界

- 文字与图片接口、工具兼容性已通过真实 API 联调；复杂真实包装、反光、遮挡及业务术语仍需逐步扩充样本，不以单张测试图推断总体准确率。
- 包装照片用于识别，创建后可在原编辑页上传正式商品主图，避免把识别原图自动公开。
- 个人提醒是运营台打开期间的站内提示，没有离线推送、短信或企业微信发送。
- 自动报告只读，不自动改价、上架、调库存、发货、审核财务或退款。
- 知识标签提供内置操作模板；尚未开放自定义文件知识库、版本发布和向量检索。
- 用量控制目前是每人每日模型请求上限与 Token 记录，没有接供应商价格表或金额预算结算。
- 批量建品为独立草稿逐项确认；未提供跨商品“一键全部提交”。
- 对话接口提供阶段事件与最终结果，不逐 Token 输出模型文本；写入结果可通过持久化草稿/执行记录恢复。
- 发货、退款、授信、财务和角色等敏感操作仍通过既有业务页面完成。
