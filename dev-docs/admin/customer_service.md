# 客户等级与服务申请

客户等级入口为管理台`/customer-levels`。管理权限继续使用`customer:manage`，新增界面不会自动给员工加权限。

## 等级和注册配置

- 可新建、编辑、启用和停用等级；编码和品牌创建后保留，不删除已有客户历史。
- 记录折扣率大于0且不超过1，最多4位小数；`1`为100%，`0.95`为95%。负责人于2026-10-24确认：客户等级仅作分类，该字段只保存资料、不自动打折。成交价使用有效客户协议价；没有有效协议价时使用商品基础价。
- 新注册仍使用当前租户启用的`normal`等级。存在多条时按最早ID选择，并在配置预检提示；没有记录时显示明确警告，不自动新建等级或导入演示数据。
- 默认等级停用可能阻止新注册，须先核对替代配置。等级启停不等于客户账号启停。
- 客户资料编辑可选择当前租户有效业务负责人。候选只返回姓名及ID，不返回员工手机号、凭据；受限业务员不能变更客户归属。

## 服务申请

小程序“我的”和采购站`/service-requests`提供申请及进度；管理台同路径提供人工处理。支持售后、资料更正、账号注销、开票和配送咨询。可搜索本人采购客户的订单号并关联，其他客户、租户的订单不可关联。

客户只能查看自己登录账号提交的申请；同一门店的另一登录账号也不能读取。管理人员须为有效的超级管理员、管理员或业务员，并具备原有`customer:manage`权限。业务员只处理负责客户，关联订单还须处于其可访问品牌范围；撤销指派或权限后下次请求即拒绝。

状态依次为待处理`pending`、处理中`processing`、已结案`completed`，也可明确驳回`rejected`。先受理再结案，每次记录须填写客户可见说明，时间线保留历史。已结束申请不能重新处理。版本号防止两个工作人员覆盖彼此的回复；遇到409须刷新并核对最新记录后再提交。

本模块是人工服务记录：申请、受理和结案不会自动退款、扣减或增加库存、修改门店资料、开具发票、停用或删除账号。工作人员先核实并在相应业务中办理，再如实记录结果。注销申请不代表立即删除历史交易；保存期限与具体售后约定由经营方确认，不在系统中编造承诺。

同一份申请失败重试沿用`clientKey`，相同内容不会重复创建，改内容复用已成功标识返回409。每个账号最多20份待处理或处理中的申请；处理时间线最多100条普通记录，达到上限仍允许明确结案。界面只展示客户可见说明，内部密码、验证码、银行完整号码等不得填写。

当前为新增源码能力。发布、数据库增量迁移、微信开发包上传与实际验收结果须分别以本轮测试和部署记录为准。
