# 商品名称与管理标签

2026-10-21，v1.2.4。沿用既有数据，不执行字段迁移或批量改名。

| 概念 | 数据库存储 | API | 管理规则 |
| --- | --- | --- | --- |
| 真实商品名 | `Product.subtitle` | `subtitle`、`displayName`、兼容读字段 `name` | 后台及 AI 草稿可修改；管理端最长 255 字，AI 草稿沿用 200 字限制 |
| 管理标签 | `Product.name` | `managementLabel` | 品牌加分类自动生成，只读；品牌分类变更继续按既有规则维护 |
| 商品编码 | `Product.code` | `code` | 自动分配；同分类共享历史序号；仅改真实名称不会重新分配 |

统一展示逻辑在 `backend/src/product/product-presentation.ts`：真实名称去除首尾空格后优先展示，否则使用原管理标签，并设置 `nameNeedsReview=true`。旧数据不自动下架、删除或改写。后台编辑页和列表提示补齐，AI 资料检查也包含缺名称项目。

商品列表、详情、常购均使用同一展示映射。读接口的 `name` 是兼容已安装客户端的展示别名，不能再当成数据库自动标签使用；管理端读取 `managementLabel`。写接口继续通过 `subtitle` 保存真实名称，客户端提供的 `name` 和 `code` 不能覆盖自动标签及编码。

品牌、分类、商品 ID、SKU ID 继续承担关联与授权；名称不作为主键。同品牌同分类的多个商品可以拥有相同管理标签，以编码和 ID 准确区分。名称修改不更新价格、规格、库存或客户可见范围。

新订单的 `OrderItem.productName` 保存创建订单时的真实商品名称；缺名旧商品沿用管理标签。之后修改目录名称不更新既有订单明细。购物车校验返回当前真实名称，客户端按 SKU ID 更新已有快照，历史订单展示继续读取历史快照。

原生小程序和采购网站均对旧接口字段保留兼容回退。小程序新增包需经微信后台正式审核发布；后端兼容字段可直接改善已经安装的旧版小程序名称展示。

验证包括真实数据库 HTTP 改名、标签及编码不变、分类序号不变、库存和 SKU 全字段不变、越权及空名称拒绝、新旧订单快照分离，以及网页和原生模拟器真实线上展示。
