# 商品、库存与接单扩展

以下扩展已于2026-10-21随 v1.3.0 / ai-20261021-10 上线后端、管理后台及采购站，线上及本地均为18项迁移。微信1.3.0开发包已上传，正式审核发布尚未完成。平台发布及验收证据见[生产部署记录](../production_deployment.md)。

线上验收读取真实商品、库存计划和权限，并使用实际模型生成批量库存与客户订单草稿，核对后取消执行；没有向正式库存或订单写入测试数据。预占、批次扣减及整单事务等写入行为已在隔离数据库验证，不以线上预览代替事务测试。现有规格默认未配置包装换算、未开启批次，需运营人员按实际资料设置。

## 第一期：商品录入与库存清单

### 规格图片与复制

- 商品编辑 → 规格编辑：从已保存的商品图库选择规格专属图片；未选时使用商品主图。删除图库图片会清除对应规格引用。
- 小程序和采购站选择规格时切换对应图片。图库继续属于商品，最多9张。
- “复制规格”复制图片、售价、包装和补货参数，允许修改后保存；使用新的自动编码，初始库存和预占均为0，不复制旧库存。

### 包装单位

- 基础销售单位选择最小可销售单位，例如袋；新增包装“箱＝20袋”。最多5种包装，换算比例是2～100000的整数。
- 包装使用同一SKU、同一份库存。200克和500克等不同商品净含量仍使用不同SKU，不合并库存。
- 客户选择2箱时，详情显示箱价和“2箱＝40袋”；进货单、协议价、订单及库存统一按40袋核算，沿用原有报价流程。箱价由基础单位价格乘换算比例计算，不新增独立整箱优惠价。
- 不认识的单位或未配置比例会阻止执行，不从商品描述或图片猜算。已有库存或预占时不能直接修改基础销售单位。

### AI批量库存

后台AI助手支持文字清单、粘贴图片或上传到货单，入口为“批量入库/盘点”。例如：

```text
按以下清单入库：
牛筋丸500克/袋2箱，批次A20261021，生产日期2026-10-01，到期日期2027-10-01。
虾滑200克/袋10袋。
请先生成草稿供我核对。
```

- 每批1～50行；入库、出库和盘点分别使用增加、减少、设为实盘总数。盘点为0有效。
- 商品名称、规格、候选、数量、输入单位、换算比例、批次和预计库存变化可核对及修改；修改后先保存再确认。
- 同SKU不同批次可分行入库/出库，库存预览按行接续；同规格同批次重复行须合并。盘点同SKU不能重复。
- 整单确认生成同一张库存单及逐行流水；重复确认只执行一次。任一行不明确、库存或配置过期、数量不足时整单回滚。
- 沿用草稿版本、摘要、10分钟有效期、权限范围及审计。聊天中回复“确认”不执行。
- 单规格一句话调整库存也支持已配置的包装单位和批次。

## 第二期：预警、补货与订单占用

入口：库存管理 → **预警、补货与批次**。

- 每规格配置最低库存、供货天数、安全库存。
- 显示账面库存、已预占、当前可见待审需求和可售数量。可售量扣除预占及已到期批次；待审需求与已预占不是相加关系。
- 面向客户的商品接口同时将原 `stockNum` 字段返回为可售量，兼容尚未更新的小程序；管理端仍返回账面库存，数据库原始库存不因此改写。
- 有经营分析和订单权限时，按当前授权范围近28天下单且已发货/完成的非样品销量计算日均需求；触发量取“人工最低库存”与“日均需求×供货天数＋安全库存”的较大值。
- 建议补足供货周期加7天的需求。无销量或无分析权限时使用人工阈值；未计采购在途，不对无数据商品编造预测。
- 可选规格、修改待补数量并保存补货草稿，支持CSV导出及待采购 → 已采购 → 已处理，也可取消。此清单用于采购跟进，不自动向供应商发送、不直接增加库存。
- 新订单在**草稿提交为待报价**时预占；待报价、待客户确认、待财务审核期间保留，财务审核通过时释放预占并正式扣库存；取消时释放，重复操作不重复执行。
- 旧订单的预占标记默认false，不补造历史预占；旧待审单审核时同样不能侵占新单已预占库存。预占不自动按时间释放，运营人员应取消不再处理的订单。

## 第三期：客户清单与批次

### 采购清单转订单

后台AI助手 → **清单转订单**，例如：

```text
为【客户全名】将这张采购清单生成订单草稿，核对实际规格、数量和客户协议价。
```

- 必须明确当前账号可操作的有效客户，按客户可见商品范围和人员品牌范围匹配SKU。
- 图片仅提取采购意图，售价从服务端的当前有效客户协议价读取，无协议价时用基础价。支持已配置的包装换算，检查起订量和可售库存。
- 多品牌按原规则拆单，显示逐行金额及品牌汇总。确认时重新核对客户、价格、配置和库存；发生变化须重新保存检查。
- 确认后只创建正式数据库中的**订单草稿**，不自动提交、报价、扣款或发通知。在订单管理核对并提交后才预占库存。
- 需要 `ai:use`、`ai:execute`、`order:read`、`order:confirm`、`customer:manage`，以及AI写入和订单草稿能力开关。

### 批次与保质期

- 在规格中明确开启，开启后保留追溯、不再关闭；入库须填写批次号和到期日期，生产日期可选，必须为真实日期。
- 启用时既有库存转为日期未知的历史批次，不编造保质期。可在批次页按实物“补登记批次”，保持总库存不变并记录零数量变更流水。
- 到期日按上海日期判断，到期当天不再允许订单出库；正常订单按先到期先出，未知日期批次排在已知日期后。未知日期库存不会自动视为过期，后台会提示补齐。
- 手动/AI出库可指定批次，未指定时按先到期先出；到期库存可以报损出库。取消已扣库存订单时退回原批次，不刷新保质期。
- 批次页显示数量、生产日期、到期日期及30天内临期/已到期提示。
- 盘点盘盈须登记批次，草稿保存后保留日期信息；完成盘点在同一事务同步SKU、批次与流水。

## 数据与验证

新增迁移：

1. `20261021130000_inventory_workflow`：SKU图片、包装、补货参数、预占、批次表、补货草稿表、流水批次分配。
2. `20261021140000_stocktake_batch_receipts`：保存盘点草稿的批次信息。

均为新增字段/表，不重命名或覆盖原有商品名、编码、库存和历史订单。先备份再迁移，禁止reset或重新导入演示数据。本地迁移已核对7类业务表的原始列数据及行数不变。

数据库集成测试使用独立 `_test` 库，覆盖整单回滚、并发重复确认、并发预占、取消释放、协议价变化、多品牌拆单、先到期出库、原批次退回、历史批次补登记和盘点草稿日期保存。模型识别与业务执行分开：自动测试不向模型供应商发送生产票据、不向客户或供应商发消息。

小程序 `config.js` 继续连接线上；本轮原生包装选择通过页面逻辑测试验证，新功能需要配套后端和小程序新包发布后才能对正式用户开放。

本地验证：后端47套件/369项、隔离数据库5套件/34项、根目录及发布Node测试93项通过；管理端单元17项、采购站单元8项通过。采购站桌面/手机28项浏览器覆盖通过，包装单位文案补充后定向2项通过；后台29项覆盖中28项首轮通过，图片权限提示文案更新后单项复验通过，新增4项流程复验通过。三套类型检查、后端lint和生产构建通过。桌面库存计划、规格弹窗、手机采购详情截图检查无页面横向溢出或脚本错误；本地真实服务4个新增/扩展接口返回200，7类业务表哈希保持一致。
