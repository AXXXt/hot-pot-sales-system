# 小程序、采购网站与运营后台检查记录

日期：2026-10-21（北京时间）。状态：修复与回归完成，后台/接口和采购网站 v1.2.3 已发布，资源校验与公网 21 页复验通过。

## 商品不可见的原因与处理

线上客户“测试门店”的客户和账号均正常，可见范围已保存为 `all`。新增商品“汴京德品鸭血制品”（商品 ID 1）由 AI 草稿创建，数据库状态为 `disabled`，因此后台可见商品数和客户分类列表均为 0。这是创建后的上架步骤没有完成，与客户等级无关。

已通过正式商品状态接口上架并留下操作审计。真实客户接口验证可见商品数为 1，鸭血制品分类可返回该商品。实际库存仍为 0，购物车校验返回不可购买；实际入库后才能下单。

该商品的工厂自产标记仍为 false；访客按现有规则只能浏览工厂自产商品。已登录的“测试门店”按其全部商品配置浏览。

## 本轮修复

1. 商品编辑页提示下架原因，提供需确认的上架入口，明确零库存限制。AI 创建结果说明后续上架、主图和入库步骤。
2. 修复规格编辑不回填 `specText`、保存时把销售单位统一覆盖成“件”的问题；保留零售价，防止重复提交。新增商品保存后进入其规格编辑页。
3. 客户可见商品配置区分未保存修改与已保存数量；零件数时提示检查上下架；自定义选择器读取完整分页。
4. 商品读取按租户、客户可见范围和员工品牌授权过滤；显式品牌筛选与授权范围取交集。客户详情隐藏停用 SKU，管理端保留编辑能力。
5. 搜索支持名称、编码、副标题、品牌及启用规格；价格排序使用当前协议价，并按实际显示价格排列规格。
6. 校验商品分页、品牌/分类参数、SKU 金额、规格文本及最小起订量，拒绝负金额、空规格和无效数量。
7. 小程序分类支持 50 件以后的分页；后续页失败保留已有商品并允许重试；避免过期请求覆盖新筛选；失效分类自动回到全部。
8. 修复原生小程序直接 require JSON 导致协议页打不开的问题：共享 JSON 生成可打包 JS，测试核对两端文案一致。调整个人中心数组读取，消除模拟器缺失 Babel helper 的运行错误。
9. 修复线上采购网站将 API 打包为 `http://127.0.0.1:3000/api/v1`，导致客户资料及商品请求失败的问题。生产默认使用同域 `/api/v1`，构建时拒绝本地 HTTP 地址。
10. 采购网站并发 401 共用一次令牌刷新；增加刷新超时及单次重试限制，异常响应清理过期凭证。
11. 升级并锁定安全依赖，包括 Nest 11.2.7、Multer 2.4.0、proxy-addr 2.0.8、nanoid 3.3.20、js-yaml 5.5.0、deepmerge-ts 8.0.2、uuid 11.1.1 及网页 Vue/HTTP 依赖。Prisma 迁移和 Excel 内存读写回环验证通过。

- 官方 npm 生产依赖审计：两套网页告警为 0；后端高危/严重为 0，保留 4 个中风险依赖节点告警：MinIO、query-string、decode-uri-component、stream-json。它们涉及 URL 解码和通知 JSON 解析。当前业务没有调用 MinIO 通知订阅，存储端点由服务端配置，文件对象键由服务端生成；后续增加通知订阅或调整存储边界前应重新评估并升级，不能将此次结果视为依赖告警全部清零。
