# Pixso 食品配送风格双端 UI 统一设计

日期：2026-07-28  
状态：已确认，实施中

## 1. 背景与目标

项目包含原生微信小程序和 Vue 3 + Element Plus 管理端。现有功能已经覆盖商品、分类、购物车、结算、订单、客户、权限和系统管理。本次将用户提供的 Pixso 食品配送视觉迁移到两端，同时保留现有功能、接口、状态管理、权限和中文业务语义。

目标视觉为深红与粉红渐变、大圆角白色卡片、暖色食品图、灰蓝辅助文字和红色主操作。管理端复用相同品牌语言，但保持桌面端信息密度，不复制移动端布局。

## 2. 目标

- 建立小程序与管理端统一的食品供应链品牌视觉。
- 保留全部页面、路由、接口调用、权限判断、状态流转和错误处理。
- 所有用户可见文案保持中文，不使用 Pixso 示例中的英文或印尼语替代业务中文。
- 商品、价格、地址、金额和订单全部使用真实接口数据，不写死示例内容。
- 通过设计令牌和公共组件实现风格统一，避免逐页复制样式。

## 3. 非目标

- 不修改后端 API、数据库或业务状态机。
- 不重写登录、权限、购物车、结算和订单逻辑。
- 不新增与当前需求无关的业务入口。
- 不为了视觉效果移除加载、空状态、错误状态、库存提示或确认流程。
- 不使用 Pixso 示例人物头像、外语文案、`Rp` 金额和虚构数据。

## 4. 方案

采用“统一设计令牌 + 公共组件重绘 + 页面布局适配”。优先保留现有 JS/TS 业务代码、事件方法和组件属性，主要修改全局令牌、WXML/Vue 模板的视觉分组和 WXSS/CSS。

核心颜色：

- 品牌深红 `#8D1C1C`
- 品牌暗红 `#660A0A`
- 品牌亮红 `#C43737`
- 暖粉背景 `#D99A9A`
- 暖米背景 `#E6BF91`
- 辅助蓝灰 `#9CABC2`
- 主要文字 `#333333`
- 次级边线 `#CDD2DE`
- 卡片白色 `#FFFFFF`

小程序大卡片使用 `28rpx` 至 `40rpx` 圆角；管理端卡片使用 `14px` 至 `18px` 圆角。阴影保持柔和，成功、警告、错误和库存状态继续使用语义色。

## 5. 中文文案契约

- 页面标题、按钮、导航、搜索提示、表单、状态、空页面和错误提示全部使用中文。
- 保留“账期额度”“协议价格”“待财务审核”“确认收货”等业务词汇。
- 不把“首页、分类、订单、我的”替换成英文。
- 商品详情主按钮使用“加入购物车”“立即购买”等真实业务中文，不使用 `APPLY FILTER`。
- 金额使用项目当前人民币规则，不使用 `Rp`。

## 6. 微信小程序

### 6.1 全局

- 保留原有页面路径和四项 TabBar：`首页`、`分类`、`订单`、`我的`。
- 页面背景调整为红色、暖粉、暖米渐变与暖灰内容区组合。
- 更新 TabBar 图标颜色、卡片、按钮、加载、错误和空状态，不改变路由。

### 6.2 首页与分类

- 首页顶部使用深红渐变，展示企业名称、客户等级和地区。
- 保留企业账期额度、剩余可用额度、搜索、常购、新品、热销、分类和商品接口。
- 搜索框、分类滚动和商品卡片采用 Pixso 的白色大圆角节奏。
- 分类页保留搜索、分类筛选、分页、错误重试和购物车浮层。

### 6.3 商品详情、购物车与结算

- 商品详情使用粉米渐变和白色分组卡，保留商品图、规格、SKU、库存、协议价格和起订量。
- 数量控件保持“减号—数量—加号”。
- 购物车保留数量修改、删除、库存校验和金额计算。
- 结算页使用票据式账单卡片，保留收货信息、支付方式、备注、优惠和应付金额。
- 所有金额与数量继续来自 Store 和接口。

### 6.4 订单、个人中心与登录

- 订单列表和详情使用白色卡片、红色关键金额和中文状态标签。
- 保留取消订单、提交财务、确认收货等状态操作。
- 个人中心保留登录状态、企业名称、等级、地区、企业资料、地址、协议价格和退出登录。
- 登录注册使用品牌渐变和白色表单卡，手机号、验证码、密码、协议及错误提示保持中文。

## 7. 管理端

### 7.1 全局框架

- 侧边栏使用暗红或深红渐变，当前菜单使用暖红高亮。
- 顶栏保留折叠、面包屑、用户名称和退出功能。
- 内容区使用暖灰背景、白色圆角卡片和浅边线。
- 通过全局变量覆盖 Element Plus 的主色、按钮、输入框、标签、分页、弹窗和抽屉。

### 7.2 页面映射

- 登录页：红色渐变背景和白色表单卡，保留认证逻辑。
- 工作台：增加品牌概览区，继续展示真实订单、销售、客户和库存指标。
- 商品与分类：保留搜索、筛选、新增、编辑、上下架、SKU、主图上传和增删改。
- 客户：保留审核、等级、联系方式、地区、商品可见范围和详情跳转。
- 订单：保留报价、提交、财务审批、发货、取消、完成和调价。
- 用户、审计、系统配置：统一标题、筛选、表格、抽屉、弹窗和空状态，不新增虚构功能。

管理端表格、筛选器和批量操作继续保持桌面端布局，不改成移动端纵向卡片堆叠。

## 8. 功能保护契约

- 小程序 `services`、`store` 和页面业务方法默认不改。
- 管理端 `api`、Pinia Store、路由守卫和权限码默认不改。
- 不修改现有路由、TabBar 路径和菜单权限码。
- 保留所有 `bindtap`、组件事件、Vue 事件和表单提交入口。
- 保留登录保护、令牌刷新、权限校验、禁用态和重复提交保护。
- 保留加载、错误、空状态、库存与订单状态。
- 如果移动节点或调整模板结构，必须逐项核对事件绑定和数据集参数。

## 9. 组件策略

小程序优先重绘搜索框、分类滚动、商品行、商品卡片、数量选择器、订单卡片、状态标签、底部操作栏、购物车浮层和反馈组件。颜色、字号、间距、圆角、阴影与动效集中在现有 Token 文件中。

管理端在全局定义品牌变量并覆盖 Element Plus，页面局部只保留布局差异。统一页面标题、筛选面板、数据卡片、状态标签和空状态，避免每页重复定义主色和卡片规则。

## 10. 实施顺序

1. 双端设计令牌和基础样式。
2. 小程序公共组件和反馈组件。
3. 小程序首页、分类、详情、购物车和结算。
4. 小程序订单、个人中心和登录。
5. 管理端全局主题、登录页和主框架。
6. 管理端工作台、商品、分类、客户、订单及通用页面。
7. 自动化检查、生产构建和关键交互验证。

## 11. 验收标准

- 两端能清晰识别为同一食品供应链品牌。
- 小程序呈现深红渐变、暖粉背景、白色大圆角卡片和食品图片重点。
- 管理端呈现品牌红导航、暖灰画布、白色圆角卡片和高效表格。
- 不出现 Pixso 示例中的英文、印尼语或 `Rp` 金额。
- 小程序路径、数据加载、筛选、详情、加购、结算、登录和订单操作正常。
- 管理端登录、权限菜单、商品、分类、客户、订单和图片上传入口正常。
- 小程序现有测试通过；管理端单元测试、类型检查、Lint 和生产构建通过。
- 核心页面完成实际渲染与点击链路检查，不能只依赖静态语法检查。

## 12. 完成定义

只有当目标页面均采用统一视觉语言、用户可见文案保持中文、功能保护契约逐项通过、自动化与构建有新鲜成功输出、核心页面完成实际交互检查，并明确记录未验证项后，才能声明改造完成。
