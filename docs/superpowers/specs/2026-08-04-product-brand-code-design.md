# 商品品牌管理与自动编码设计

## 1. 背景

当前商品编辑页能够保存商品编码，但商品列表读取的是不存在的 `productCode` 字段，而后端实际返回 `code`，因此列表中的“商品编码”为空。

同时，现有商品创建流程没有品牌选择，后端会默认取当前租户第一个启用品牌，无法稳定执行“品牌名称 + 分类名称”的商品命名规则，也无法按品牌和分类生成统一商品编码。

本设计增加品牌管理、品牌选择、后端自动命名和分类全局历史序号，并将相关规则固化到数据库事务、管理端交互和测试中。

## 2. 目标

- 修复商品列表无法显示已保存商品编码的问题。
- 增加管理端品牌管理功能。
- 新建商品时必须选择品牌和分类。
- 商品名称由系统按照“品牌名称 + 分类名称”自动生成。
- 商品编码由系统按照“品牌前缀-分类拼音-历史序号”自动生成。
- 同一分类的历史序号跨品牌全局累计。
- 商品、品牌和分类删除时保留历史业务关系与历史序号。
- 将生成逻辑放在后端，防止前端篡改、并发重复和多端规则不一致。

## 3. 已确认业务规则

### 3.1 商品名称

商品名称公式：

```text
商品名称 = 品牌名称 + 分类名称
```

品牌名称与分类名称之间不增加空格或连接符。

示例：

```text
品牌：德品
分类：鸭血
商品名称：德品鸭血
```

商品种类直接使用已选择的分类名称，不增加单独的“商品种类”输入字段。

### 3.2 商品编码

商品编码公式：

```text
商品编码 = 品牌编码前缀 + "-" + 分类拼音 + "-" + 分类历史序号
```

示例：

```text
品牌名称：德品
品牌编码前缀：DEPIN
分类名称：鸭血
分类拼音：YaXue
分类历史序号：001
商品编码：DEPIN-YaXue-001
```

### 3.3 品牌编码前缀

- 根据品牌中文名称自动转换为无声调大写拼音。
- 只允许大写英文字母和数字。
- 创建或编辑品牌时允许管理员人工校正。
- 在同一租户内必须唯一。
- 示例：`德品` 自动生成 `DEPIN`。

### 3.4 分类拼音

- 直接根据分类名称转换，不在商品表单中单独填写。
- 使用无声调拼音。
- 每个汉字对应拼音的首字母大写，其余字母小写。
- 去除空格、连接符和其他非字母数字字符。
- 示例：`鸭血` 转换为 `YaXue`。

分类重命名后，新创建或重新生成编码的商品使用新分类名称对应的拼音；已有商品编码保持不变。

### 3.5 历史序号

- 每个分类维护一个跨品牌共享的历史序号。
- 序号只增不减。
- 商品删除、归档、移动分类或更换品牌时，不回收旧序号。
- 序号最少补齐三位：`1` 为 `001`，`99` 为 `099`。
- 超过 `999` 后自然扩展：`1000` 直接显示为 `1000`。

跨品牌示例：

```text
DEPIN-YaXue-001
MEIWEI-YaXue-002
DEPIN-YaXue-003
```

### 3.6 编码变更

- 商品首次创建时由后端生成正式编码。
- 商品编码不允许直接人工修改。
- 商品品牌或分类发生变化时，必须二次确认。
- 确认后使用目标分类的下一个历史序号生成新编码。
- 旧编码永久作废，不复用。
- 只修改副标题、规格、图片、描述或状态时，不生成新编码。

### 3.7 品牌或分类重命名

- 品牌或分类名称发生变化时，同步更新关联商品名称。
- 已有商品编码不批量修改。
- 品牌编码前缀修改后，仅影响以后新建或重新生成编码的商品。

## 4. 数据模型设计

### 4.1 Brand

复用现有 `Brand` 模型：

- `name`：品牌名称。
- `code`：品牌编码前缀。
- `sortOrder`：排序。
- `status`：`active` 或 `disabled`。
- `logoUrl`、`description`：保留现有扩展字段。

不新增重复的品牌前缀字段，直接将 `Brand.code` 作为商品编码品牌段。

### 4.2 ProductCategory

在 `ProductCategory` 增加：

```prisma
productSequence Int @default(0) @map("product_sequence")
```

该字段表示此分类已分配的最大历史序号，而不是当前有效商品数量。

### 4.3 Product

复用现有字段：

- `brandId`：必选品牌。
- `categoryId`：新建商品时必选分类。
- `name`：后端生成的名称快照。
- `code`：后端生成的唯一编码快照。

`Product.code` 继续使用租户内唯一约束。商品编码最大长度保持数据库现有的 64 个字符；生成结果超过限制时拒绝保存并返回明确错误，不进行可能产生歧义的静默截断。

## 5. 后端事务设计

### 5.1 新建商品

后端收到新建请求后执行一个数据库事务：

1. 校验品牌属于当前租户且状态为 `active`。
2. 校验分类属于当前租户且状态为 `active`。
3. 原子递增分类的 `productSequence`。
4. 根据品牌和分类生成商品名称。
5. 根据品牌前缀、分类拼音和新序号生成商品编码。
6. 检查租户内编码唯一性。
7. 创建商品并返回正式名称与编码。

分类计数器的递增和商品创建必须在同一事务内完成。商品创建失败时事务回滚，不留下无效序号；已经成功创建过的商品被删除或归档时，序号不回退。

### 5.2 并发创建

- 分类计数器通过数据库原子递增和行级锁串行分配。
- 同一分类同时创建多个商品时，每个事务获得不同序号。
- 创建前仍检查最终商品编码是否已存在，以兼容旧数据或人工导入数据。
- 如果发现旧编码冲突，事务继续分配下一个序号，而不是覆盖旧商品或返回通用 `500`。

### 5.3 编辑商品

- 后端先读取商品当前的 `brandId` 和 `categoryId`。
- 品牌和分类均未变化时，忽略客户端对 `name` 和 `code` 的修改，只更新其他允许字段。
- 品牌或分类发生变化时，按新建商品的生成流程分配目标分类新序号，并更新商品名称与编码。
- 旧编码不建立复用池。

### 5.4 品牌和分类重命名

- 品牌名称变化时，在同一事务中更新该品牌下所有商品的名称。
- 分类名称变化时，在同一事务中更新该分类下所有商品的名称。
- 同步名称时使用商品实际关联的品牌名称和分类名称重新组合。
- 不修改已有商品编码，不递增分类历史序号。

## 6. 品牌管理设计

### 6.1 管理端功能

左侧菜单增加“品牌管理”，页面提供：

- 品牌名称。
- 品牌编码前缀。
- 关联商品数量。
- 排序。
- 状态。
- 新建、编辑、删除和恢复操作。

输入品牌名称时自动生成编码前缀，管理员可以在保存前修改。

### 6.2 品牌管理接口

增加受 `JwtAuthGuard` 保护的管理接口：

- 品牌管理列表，支持状态筛选。
- 创建品牌。
- 编辑品牌。
- 删除品牌。
- 恢复已停用品牌。

现有公开品牌列表接口继续只返回启用品牌，供小程序和商品选择使用。

### 6.3 品牌安全删除

- 没有关联任何历史商品的品牌可以物理删除。
- 已关联商品的品牌执行删除时改为 `disabled`。
- 已停用品牌不出现在新建商品的品牌选择中。
- 编辑关联旧商品时仍显示其当前品牌，并标记“已停用”。
- 管理端支持筛选已停用品牌并恢复。

删除响应需要明确返回执行方式：

```json
{
  "id": 3,
  "deletionMode": "disabled",
  "linkedProductCount": 12
}
```

## 7. 分类删除调整

为保证分类历史序号不会因为分类记录被删除而丢失，分类删除采用与品牌一致的规则：

- 没有关联任何历史商品的分类可以物理删除。
- 已产生历史商品的分类执行删除时改为 `disabled`。
- 已停用分类不出现在新建商品的分类选择中。
- 管理端支持恢复已停用分类。
- 已归档商品仍计入“历史商品关联”。

## 8. 商品管理端设计

### 8.1 商品编辑页

- 增加必选品牌下拉框。
- 分类继续使用现有下拉选择，不增加商品种类输入框。
- 商品名称改为只读。
- 商品编码改为只读。
- 选择品牌和分类后实时预览商品名称。
- 新建商品保存前，编码显示格式预览，例如 `DEPIN-YaXue-***`。
- 保存成功后显示后端返回的正式编码。
- 编辑已有商品时显示实际商品编码。
- 更换品牌或分类时弹出二次确认，说明将分配新编码且旧编码不会复用。

### 8.2 商品列表

- 商品编码列绑定后端实际字段 `code`，不再读取不存在的 `productCode`。
- 搜索框同时匹配商品名称和商品编码。
- 新建或重新生成编码后，列表刷新即可显示正式编码。

## 9. DTO 与兼容策略

- `CreateProductDto` 增加必选 `brandId`。
- `categoryId` 保持必选。
- 商品创建和品牌/分类变更时，后端忽略客户端传入的 `name` 和 `code`。
- 管理端新版本不再提交可编辑的商品名称和商品编码。
- 现有商品的历史名称和编码不批量重写。
- 现有小程序只读取商品，不受商品创建 DTO 调整影响。

## 10. 数据迁移

### 10.1 分类历史计数器

迁移增加 `product_sequence`，并对每个现有分类计算初始值：

```text
初始历史序号 = max(该分类历史商品总数, 现有商品编码的最大数字后缀)
```

历史商品总数包含 `active`、`disabled` 和 `archived` 商品。

### 10.2 旧商品编码

- 已有非空商品编码全部保留。
- 不按照新规则批量重写旧商品编码。
- 列表字段修复后直接展示现有 `Product.code`。
- 发现空编码或重复编码时，迁移前停止并输出待修复记录，避免静默生成错误数据。

### 10.3 旧品牌编码

- 将旧品牌编码规范为大写字母数字格式。
- 无法从旧编码得到有效前缀时，根据品牌名称自动生成。
- 规范化后发生重复时停止迁移并输出冲突品牌，由管理员确认前缀。
- 修改品牌前缀不修改已有商品编码。

## 11. 错误处理

后端返回明确业务错误：

- 品牌不存在或已停用。
- 分类不存在或已停用。
- 品牌编码前缀格式无效。
- 品牌编码前缀重复。
- 自动生成的商品编码超过长度限制。
- 旧数据导致商品编码无法分配。
- 品牌或分类不存在。

数据库唯一约束错误必须转换为业务冲突响应，不允许以通用 `500 SYS_0001` 返回。

- 商品详情和购物车保存后端返回的真实 `brandId`；加入不同品牌商品时前端阻止混入。
- 购物车校验接口回填 SKU 对应商品的权威 `brandId`，用于识别历史缓存中的跨品牌数据。
- 后端创建订单时从 SKU 对应商品推导订单 `brandId`；混合品牌请求返回 `ORD_1002`，不创建错误归属订单。
- 品牌和分类管理分别展示当前商品数与已归档商品数，不再把安全删除数据计入当前关联数。
- 小程序分类接口返回鸭血、毛肚、豆制品、鸭副四个启用分类；空分类不再被隐藏。

### 15.6 有意保留的兼容行为

- 不批量改写任何既有商品编码，历史 `Product.code` 原样保留并直接展示。
- 保留现有 `ProductCategory.code` 数据字段；管理端仍不增加独立分类编码输入，创建分类时由现有分类名称兼容填充该字段。
- 公共分类接口仍只返回启用分类，但不要求分类下必须已有可见商品；管理接口单独返回启用和停用分类、当前商品数、归档商品数及历史总数。
- 商品普通资料修改不重新生成编码；只有品牌或分类变化才消耗新的分类历史序号。
