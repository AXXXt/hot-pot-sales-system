# 商品主图上传设计

日期：2026-07-28  
状态：已实施并完成自动化与本地联调验证

## 1. 背景

管理端商品编辑页当前通过“图片地址”文本框维护 `mainImageUrl`，管理员必须先在其他位置上传图片，再复制 URL。项目已经配置 MinIO，但现有 MinIO Provider 只用于健康检查，尚未提供文件上传能力。

本次将商品图片维护方式改为单张主图上传。管理员选择图片后立即上传并预览，保存商品时继续提交现有 `mainImageUrl` 字段，因此不需要修改商品数据表。

## 2. 目标

- 将商品编辑页的图片 URL 输入框替换为单张图片上传组件。
- 选图后立即上传，上传成功后显示缩略图。
- 支持替换和移除当前主图。
- 仅允许 JPG、PNG、WebP，单张最大 5MB。
- 前端提供即时提示，后端执行不可绕过的最终校验。
- 图片存入现有 MinIO，并返回可供管理端和小程序访问的 URL。
- 商品创建、更新和读取继续使用现有 `mainImageUrl` 字段。

## 3. 非目标

- 不支持多图上传或拖动排序。
- 不修改商品 `images` JSON 字段。
- 不为图片增加裁剪、压缩、水印或格式转换。
- 不在本次实现图片资源后台管理和批量清理。
- 不自动删除已经上传到 MinIO 的历史图片，避免误删已发布或被复用的资源。
- 不改变商品保存、SKU 管理和商品展示的其他业务逻辑。

## 4. 方案选择

采用“管理端上传到 NestJS，NestJS 再写入 MinIO”的后端中转方案。

不采用浏览器直传 MinIO，因为直传需要额外的预签名接口、MinIO CORS 配置和两阶段错误处理，超出当前单图上传需求。也不采用本地目录或数据库存图，因为它们不符合现有 Docker 和 MinIO 基础设施。

## 5. 管理端设计

### 5.1 页面交互

商品编辑页删除“图片地址”输入框，改为单图上传区域：

- 没有图片时显示上传入口和格式、大小提示。
- 选择合法图片后立即开始上传并显示上传状态。
- 上传成功后显示主图缩略图，以及“更换图片”“移除图片”操作。
- 编辑已有商品时直接回显 `mainImageUrl` 对应图片。
- 更换图片上传失败时保留原图片，不清空已有 URL。
- 点击“移除图片”只清空当前表单中的 `imageUrl`，保存商品后数据库字段更新为空；不直接删除 MinIO 对象。
- 上传进行中禁用“保存商品”，避免提交尚未完成的图片状态。

### 5.2 前端校验

选择文件后先检查：

- MIME 类型属于 `image/jpeg`、`image/png`、`image/webp`。
- 文件大小不超过 5MB。

不符合要求时不发送请求，并使用 Element Plus 消息明确提示原因。前端校验仅用于改善体验，不能替代后端校验。

### 5.3 API 调用

在管理端商品 API 中新增：

- `uploadProductImage(file: File)`

该方法使用现有 Axios 实例发送 `multipart/form-data`，沿用现有访问令牌、刷新令牌和统一错误处理。上传成功后读取响应中的 `url` 并赋值给 `form.imageUrl`。商品保存请求仍按现有结构提交：

```json
{
  mainImageUrl: http://127.0.0.1:9000/b2b-miniapp/products/2026/07/example.webp
}
```

## 6. 后端设计

### 6.1 上传接口

新增接口：

- `POST /api/v1/uploads/product-image`

接口要求：

- 使用现有 `JwtAuthGuard`，权限边界与商品创建、更新接口保持一致。
- 请求类型为 `multipart/form-data`。
- 文件字段名为 `file`。
- 单次只接收一个文件。
- Multer 层限制最大文件大小为 5MB。

成功响应数据：

```json
{
  url: http://127.0.0.1:9000/b2b-miniapp/products/2026/07/uuid.webp,
  objectKey: products/2026/07/uuid.webp
}
```

响应继续由现有 `SuccessInterceptor` 包装为统一的 `code / message / data / requestId` 结构。

### 6.2 文件校验

后端执行以下校验：

- 文件存在且大小大于 0。
- 文件大小不超过 5MB。
- 声明的 MIME 类型属于 JPG、PNG、WebP。
- 文件头特征与声明格式一致，拒绝仅修改扩展名或 MIME 类型的伪装文件。

对象扩展名由后端识别出的真实格式决定，不直接信任原始文件名。对象名使用 UUID，防止路径穿越、重名覆盖和特殊字符问题。

### 6.3 MinIO 存储

引入官方 MinIO Node.js SDK，并将现有 MinIO Provider 扩展为可复用的存储能力：

- 保留现有 `health()` 健康检查。
- 使用已有 `MINIO_ENDPOINT`、`MINIO_PORT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_BUCKET` 和 `MINIO_USE_SSL` 配置。
- 新增 `MINIO_PUBLIC_URL`，用于生成浏览器和小程序可访问的公开地址；开发环境默认值为 `http://127.0.0.1:9000`。
- 上传前确保配置的 Bucket 存在。
- 对象路径固定为 `products/YYYY/MM/<uuid>.<ext>`。
- 写入正确的 `Content-Type`，并设置适合公开商品图片的缓存元数据。
- MinIO 公开读取策略只覆盖 `products/*` 前缀，不公开 Bucket 中其他对象。

生产环境必须将 `MINIO_PUBLIC_URL` 配置为真实可访问的 HTTPS 域名或 CDN 地址，不能沿用本地地址。

### 6.4 错误处理

| 场景 | 处理 |
| --- | --- |
| 未选择文件或文件为空 | 返回 `400`，提示请选择商品图片 |
| 格式不支持 | 返回 `400`，提示仅支持 JPG、PNG、WebP |
| 文件超过 5MB | 返回 `400`，提示图片不能超过 5MB |
| 文件头与类型不一致 | 返回 `400`，提示图片文件无效 |
| MinIO 不可用或上传失败 | 返回 `503` 或统一存储错误，数据库和商品资料不发生变化 |
| 更换图片上传失败 | 管理端保留原图并允许重试 |

错误响应继续使用现有全局异常过滤器，不在控制器中返回伪成功结果。

## 7. 数据流

1. 管理员在商品编辑页选择图片。
2. 管理端完成格式和 5MB 大小校验。
3. 管理端调用上传接口并进入上传状态。
4. 后端验证文件内容，生成对象路径并写入 MinIO。
5. 后端返回公开 URL 和对象 Key。
6. 管理端将 URL 写入 `form.imageUrl` 并显示缩略图。
7. 管理员点击“保存商品”。
8. 现有商品创建或更新接口将 URL 保存到 `Product.mainImageUrl`。
9. 管理端和小程序继续通过现有字段展示商品主图。

上传和商品保存是两个独立步骤。若图片上传成功但管理员未保存商品，MinIO 中可能出现未引用对象；本次不做自动删除，以避免错误清理，后续可通过独立的对象盘点任务处理。

## 8. 测试设计

### 8.1 后端自动测试

- JPG、PNG、WebP 文件头识别正确。
- MIME 类型与文件头不一致时拒绝上传。
- 空文件和不支持格式被拒绝。
- 超过 5MB 的文件被 Multer 限制拒绝。
- 合法文件使用 UUID 和日期目录生成对象路径。
- 存储服务以正确 Content-Type 写入 MinIO，并返回配置化公开 URL。
- 上传接口需要有效 JWT。
- MinIO 抛出异常时接口不返回成功结果。

### 8.2 管理端自动测试

- JPG、PNG、WebP 且不超过 5MB 时通过前端校验。
- 不支持格式和超过 5MB 时返回明确错误。
- 上传响应 URL 能正确写入商品保存参数。

管理端目前没有 Vue 组件测试基础，本次优先将文件校验提取为纯函数并使用现有 Vitest 测试；页面模板通过 TypeScript、Vue 类型检查和构建验证。

### 8.3 人工验收

1. 新建商品时上传一张合法图片，立即看到预览，保存后重新进入页面仍能回显。
2. 编辑商品时更换图片，保存后商品列表、小程序列表和详情使用新图片。
3. 上传 JPG、PNG、WebP 均成功。
4. 上传 GIF、文本伪装图片或超过 5MB 的图片时被拒绝。
5. 模拟后端或 MinIO 不可用时，页面提示失败且原图不丢失。
6. 上传进行中无法保存商品。
7. 移除图片并保存后，商品主图字段为空，页面不再显示旧图。

## 9. 验收标准

- 商品编辑页不再要求管理员手工填写图片 URL。
- 单张主图能够立即上传、预览、替换和移除。
- 前后端均强制 JPG、PNG、WebP 和 5MB 限制。
- 商品保存继续使用 `mainImageUrl`，不需要 Prisma 迁移。
- 上传失败不会覆盖或清空已有商品图片。
- 后端测试、管理端单元测试、类型检查和构建全部通过。
- 本地联调确认 MinIO 对象存在，并且返回 URL 可以实际打开图片。
