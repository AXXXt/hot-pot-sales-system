# 客户商品可见范围重构设计

日期：2026-07-27  
状态：已实施；品牌相关规则已由 2026-08-04 品牌管理设计更新

> 2026-08-04 更新：客户可见范围仍按本文执行；商品品牌创建、筛选和下单归属以 `2026-08-04-product-brand-code-design.md` 为准。

## 1. 背景

当前系统使用商品“可见性”和客户“渠道类型”共同表达商品范围，但两者容易出现配置不一致，已经导致管理端显示有货、客户却看不到或无法下单的问题。商品编辑中的品牌选择也不符合当前单工厂、单默认品牌的运营方式。

新的规则改为由客户直接决定可见商品范围：大型连锁默认只看工厂自产商品，小型经销商和门店可以看全部商品，特殊客户可以精确配置商品。游客只能浏览工厂自产商品。

## 2. 目标

- 商品编辑删除品牌选择和旧可见性功能，新增“工厂自产”开关。
- 客户管理删除渠道类型，客户详情新增“可见商品”卡片。
- 支持“工厂自产、全部商品、自定义商品”三种客户可见模式。
- 游客、未配置客户和新注册客户默认只看工厂自产商品。
- 商品列表、详情、SKU 和订单提交使用同一套后端可见性规则。
- 将“标准客户”调整为“普通客户”，新注册用户默认绑定普通客户等级。

## 3. 非目标

- 不删除底层品牌、分类或订单中的品牌关系。
- 不改变客户类型 `customerType`；本次只删除渠道类型 `channelType`。
- 不按客户等级自动推导商品范围。客户等级继续负责等级名称、折扣等现有能力，商品范围由客户可见模式独立控制。
- 不改变协议价优先级、库存计算、订单状态流转和支付审核流程。

## 4. 核心业务规则

### 4.1 商品属性

商品新增布尔字段 `isFactoryProduct`，表示是否为工厂自产商品。新建商品默认关闭，管理员在商品编辑页通过“工厂自产”开关维护。

旧数据按以下规则迁移：

- 旧 `visibilityType = 1`（仅限连锁）迁移为 `isFactoryProduct = true`。
- 旧 `visibilityType = 2`（全渠道）迁移为 `isFactoryProduct = false`。
- 数据迁移完成后删除旧 `visibilityType` 字段及其 DTO、服务和界面逻辑。

### 4.2 客户可见模式

客户新增 `productVisibilityMode`：

| 模式 | 含义 | 适用对象 |
| --- | --- | --- |
| `factory` | 仅可见启用的工厂自产商品 | 新客户、大型连锁 |
| `all` | 可见全部启用商品 | 小门店、小型经销商 |
| `custom` | 仅可见管理员勾选且启用的商品 | 有特殊目录要求的客户 |

新注册客户和迁移前的现有客户统一默认 `factory`。管理员可在客户详情页修改模式。

保存 `custom` 模式时必须至少选择一个商品。切换并保存为 `factory` 或 `all` 时，清空该客户之前的自定义关联，避免以后误恢复过期授权。

### 4.3 游客和内部账号

- 未登录游客仅可查看启用且 `isFactoryProduct = true` 的商品。
- 已登录客户根据所属客户的 `productVisibilityMode` 过滤。
- 客户用户异常地没有绑定客户时，按游客规则处理，不扩大权限。
- 管理员、销售、客服等内部账号不受客户商品范围限制，管理端仍可查看全部商品。

### 4.4 客户等级

将现有等级代码 `standard` 和名称“标准客户”更新为代码 `normal`、名称“普通客户”。记录 ID 保持不变，因此现有客户关联、折扣和价格规则不变。

新注册流程按当前租户查找启用的 `normal` 等级并自动绑定。若普通客户等级不存在，注册事务失败并记录明确错误，不创建无默认等级的半成品客户数据。开发种子数据同步改为创建或更新“普通客户”。

## 5. 数据模型

### 5.1 Product

新增：

- `isFactoryProduct Boolean @default(false) @map("is_factory_product")`

删除：

- `visibilityType`

`brandId` 及品牌关联继续保留，现有商品品牌数据不变。管理端创建或变更商品时必须显式选择启用品牌，后端负责校验并生成商品名称与编码。小程序在没有显式品牌选择控件时不得注入默认 `brandId`，商品列表应返回当前客户可见范围内的全部品牌商品；只有调用方明确选择品牌时才按 `brandId` 过滤。

### 5.2 Customer

新增：

- `productVisibilityMode ProductVisibilityMode @default(factory)`
- `visibleProducts CustomerVisibleProduct[]`

删除：

- `channelType`

保留：

- `customerType`，其现有展示和业务含义不变。

### 5.3 CustomerVisibleProduct

新增客户与商品关联表，字段包括：

- `id`
- `tenantId`
- `customerId`
- `productId`
- `createdAt`

约束：

- `(tenantId, customerId, productId)` 唯一。
- 客户和商品必须属于同一租户。
- 删除客户时级联删除关联；商品删除策略遵循现有商品归档约束，业务上优先归档而非物理删除。

## 6. 后端设计

### 6.1 客户可见商品接口

新增接口：

- `GET /api/v1/customers/:id/product-visibility`
- `PUT /api/v1/customers/:id/product-visibility`

读取接口返回：

- `mode`
- `productIds`
- 已选商品摘要，供管理端直接回显名称、分类和状态。

保存接口请求体：

```json
{
  "mode": "custom",
  "productIds": [1, 2, 3]
}
```

保存操作在 Prisma 事务内完成。服务端验证客户、商品和租户归属；`custom` 模式拒绝空数组、重复 ID、不存在商品、停用商品和跨租户商品。`factory`、`all` 模式忽略并清空自定义商品 ID。

### 6.2 统一商品访问条件

产品服务提供单一的客户可见条件解析逻辑，列表、详情、SKU 和下单校验共同使用：

- 游客或无客户绑定用户：`status = active AND isFactoryProduct = true`。
- `factory`：`status = active AND isFactoryProduct = true`。
- `all`：`status = active`。
- `custom`：`status = active AND product.id IN customerVisibleProducts`。
- 内部账号：不增加客户范围条件，保留管理端原有状态筛选能力。

不可见商品的详情和 SKU 接口统一返回 `404`，避免泄露商品是否存在。订单创建或更新时必须再次校验商品可见性，不能信任小程序提交的商品 ID 或购物车缓存。

### 6.3 DTO 和兼容处理

- 商品创建、更新 DTO 删除 `visibilityType`，不再接收管理端 `brandId`。
- 客户创建、更新 DTO 删除 `channelType`。
- 客户详情响应新增 `productVisibilityMode`，不再返回渠道类型。
- 商品响应新增 `isFactoryProduct`。
- 保留协议价字段和现有价格计算逻辑；过滤完成后再进行客户协议价个性化。

## 7. 管理端设计

### 7.1 商品编辑

- 删除品牌下拉框及品牌列表请求。
- 删除“可见性”下拉框。
- 新增“工厂自产”开关。
- 编辑旧商品时回显迁移后的自产标记，新建商品默认关闭。

### 7.2 客户管理

- 客户列表的新建弹窗删除渠道类型。
- 客户详情基本信息和编辑弹窗删除渠道类型。
- 客户详情新增独立“可见商品”卡片，不嵌套在基本信息卡片中。

卡片包含：

- `工厂自产 / 全部商品 / 自定义商品` 三段模式选择。
- 当前模式说明和当前可见商品数量。
- 自定义模式下提供商品名称搜索、分类筛选和多选列表。
- 已选数量、取消和保存操作。
- 停用商品不允许新选；若历史关联商品后来停用，在回显中标记停用并要求保存时移除。

## 8. 小程序行为

- 首页、分类商品列表和搜索结果只展示当前身份可见商品。
- 商品详情和规格请求遇到不可见商品时展示“商品不存在或暂不可购买”，并返回商品列表。
- 客户可见范围变化后，购物车中的不可见或停用商品标记为“不可购买”，不参与结算。
- 结算前刷新商品有效性和价格；后端仍进行最终校验。
- 游客登录或客户配置变更后刷新商品列表缓存，避免继续显示旧范围数据。

## 9. 异常处理

| 场景 | 处理 |
| --- | --- |
| 自定义模式未选商品 | 返回 `400`，提示至少选择一个商品 |
| 商品不属于当前租户 | 返回 `400`，不保存任何变更 |
| 商品已停用或不存在 | 返回 `400` 并指出无效商品 |
| 客户访问不可见详情或 SKU | 返回 `404` |
| 购物车包含不可见商品 | 前端标记不可购买；下单接口返回明确业务错误 |
| 租户没有默认启用品牌 | 商品创建返回 `400`，提示先配置默认品牌 |
| 普通客户等级缺失 | 注册事务失败并记录配置错误 |

## 10. 迁移顺序

1. 新增 `is_factory_product`、`product_visibility_mode` 和客户商品关联表。
2. 按旧 `visibility_type` 回填工厂自产标记。
3. 将所有现有客户的可见模式回填为 `factory`。
4. 将客户等级 `standard / 标准客户` 原记录更新为 `normal / 普通客户`。
5. 部署使用新字段和新规则的后端与管理端。
6. 删除 `visibility_type`、`channel_type` 及对应代码。
7. 核对自产商品清单，并为小门店、小型经销商切换为 `all` 或配置 `custom`。

迁移和部署应在同一维护窗口完成。第 7 步是上线后的必要运营检查，不以名称或分类自动猜测自产商品。

## 11. 测试与验收

### 11.1 后端自动测试

- 游客只能获取工厂自产商品。
- 新客户自动绑定普通客户等级并使用 `factory` 模式。
- `factory`、`all`、`custom` 三种客户列表结果正确。
- 不可见商品的详情和 SKU 返回 `404`。
- 不可见商品不能通过伪造请求加入订单或提交订单。
- 自定义列表保存、替换、清空规则和事务回滚正确。
- 空自定义列表、停用商品、非法 ID、跨租户商品均被拒绝。
- 内部账号仍可管理全部商品。
- 协议价在过滤后的可见商品中继续正确生效。

### 11.2 构建与数据验证

- `prisma validate` 和迁移执行成功。
- 后端完整测试通过，不能只运行新增用例。
- 管理端类型检查和生产构建通过。
- 小程序 WXML、JavaScript 编译通过。
- 实际数据库中不存在“标准客户”展示值，新注册客户绑定“普通客户”。
- 抽查游客、大型连锁、小门店、自定义客户四种身份的列表、详情、规格、购物车和下单结果。

## 12. 验收标准

- 商品编辑页不再出现品牌和旧可见性，只保留明确的“工厂自产”开关。
- 客户管理中不再出现渠道类型。
- 客户详情可以独立配置三种商品可见模式并立即影响小程序。
- 游客和新客户只看到工厂自产商品，小门店可配置为看到全部商品。
- 任何不可见商品都不能通过详情、SKU 或伪造订单请求绕过限制。
- “标准客户”被“普通客户”替代，历史价格规则和客户关联保持有效。
