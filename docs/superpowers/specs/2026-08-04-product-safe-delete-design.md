# 商品安全删除功能设计

## 1. 目标

在管理后台商品列表中增加单个删除和批量删除能力，方便清理多余商品。删除采用安全归档，不物理移除数据库记录，不破坏 SKU、订单、协议价或客户可见范围等历史关联。

## 2. 核心决策

- 使用现有 `ProductStatus.archived` 表示已删除商品。
- 已归档商品从管理端默认商品列表和小程序商品接口中消失。
- 不删除商品关联的 SKU、订单项、协议价、价格历史和客户可见关系。
- 单个删除和批量删除均仅允许已登录的管理端用户调用。
- 删除操作在当前版本中不提供回收站和恢复入口。
- 不新增数据库字段，不需要 Prisma 迁移。

## 3. 后端接口

### 3.1 单个安全删除

- 方法：`DELETE /api/v1/products/:id`
- 鉴权：`JwtAuthGuard`
- 行为：将指定商品状态更新为 `archived`。
- 幂等性：商品已经是 `archived` 时仍返回成功。
- 商品不存在时返回 `404` 和商品不存在错误信息。
- 响应：

```json
{
  "id": 17,
  "status": "archived"
}
```

### 3.2 批量安全删除

- 方法：`PATCH /api/v1/products/batch-archive`
- 鉴权：`JwtAuthGuard`
- 请求体：

```json
{
  "productIds": [3, 7, 7]
}
```

- 校验：数组不能为空，所有 ID 必须是正整数。
- 行为：对 ID 去重，只更新尚未归档的商品。
- 响应：

```json
{
  "productIds": [3, 7],
  "status": "archived",
  "updatedCount": 2
}
```

## 4. 后端服务设计

在 `ProductService` 中增加：

- `archiveProduct(id: number)`：查询商品、处理不存在情况、幂等归档并返回状态。
- `batchArchiveProducts(productIds: number[])`：校验、去重并通过 `updateMany` 批量归档。

现有商品列表在 `includeDisabled=true` 时已经使用 `status: { not: 'archived' }`，小程序公开列表只返回 `active` 商品，因此归档后不需要额外修改查询逻辑。

## 5. 管理端交互设计

### 5.1 单个删除

- 商品行操作区增加红色文字按钮“删除”。
- 点击后显示危险确认框，包含商品名称。
- 提示文案明确说明商品会从管理端和小程序隐藏，但历史订单会保留。
- 删除成功后显示成功消息并刷新当前页。

### 5.2 批量删除

- 表格允许选择已上架和已下架商品。
- 批量工具栏增加红色“批量删除”按钮。
- 确认框显示选择数量和安全归档说明。
- 成功消息显示实际归档数量。
- 如果删除后当前分页为空且不是第一页，返回上一页并重新加载。

### 5.3 与批量下架共存

- “批量下架”只处理选中记录中状态为 `active` 的商品。
- 没有选中已上架商品时禁用“批量下架”。
- “批量删除”处理所有选中商品，不区分 `active` 和 `disabled`。
- 工具栏分别显示已选择总数和其中已上架数量。

## 6. 管理端 API

在 `admin-web/src/api/product.ts` 中增加：

- `deleteProduct(id)`：调用 `DELETE /products/:id`。
- `batchArchiveProducts(productIds)`：调用 `PATCH /products/batch-archive`。

## 7. 错误处理

- 用户取消确认框时不发送请求，也不显示错误消息。
- 接口失败时沿用 Axios 拦截器的统一错误提示。
- 单个删除不存在的商品时显示后端返回的不存在提示。
- 批量请求包含非法 ID 时返回 `400`，不执行部分归档。

## 8. 测试设计

### 8.1 后端测试

- 单个商品能够更新为 `archived`。
- 重复删除已归档商品保持成功。
- 删除不存在商品返回 `NotFoundException`。
- 批量删除会去重并调用 `updateMany`。
- 空数组、非整数和非正数 ID 被拒绝。

### 8.2 管理端契约测试

- 商品 API 暴露单个和批量安全删除方法及正确路由。
- 商品列表包含单个“删除”和“批量删除”入口。
- 单个删除确认文案包含商品名称。
- 批量下架只提交已上架商品 ID。
- 批量删除提交全部选中商品 ID。

## 9. 验收标准

- 管理员可以安全删除单个商品。
- 管理员可以选择多个商品并批量安全删除。
- 已删除商品不再出现在管理端商品列表和小程序中。
- 商品相关历史订单和 SKU 数据仍可被已有订单正常引用。
- 单个及批量删除均有明确确认提示和成功反馈。
- 后端测试、管理端测试和现有小程序契约测试全部通过。

## 10. 计数与分类展示补充规则

- `archived` 商品继续保留在数据库中，这是安全删除的预期行为，不代表商品仍可售。
- 品牌管理和分类管理中的“当前商品数”只统计 `active`、`disabled` 商品，不包含 `archived`。
- 管理端单独展示“已归档”数量，避免将归档历史误认为当前商品。
- 品牌和分类的删除方式仍按历史商品总数判断；存在归档历史时只安全停用，不误报为可永久删除。
- 小程序分类接口返回全部启用分类，即使分类当前没有可售商品；进入空分类后展示正常空状态。
- 2026-08-04 数据审计确认演示品牌存在 20 个归档商品，其中 19 个没有订单明细引用，1 个 SKU 存在 2 条订单明细引用。本次未执行任何物理删除。

## 11. 不在本次范围

- 商品回收站。
- 恢复已删除商品。
- 永久物理删除。
- 自动清理商品图片文件。
- 自动物理清理无订单引用的归档演示商品。
