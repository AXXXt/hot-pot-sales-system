# 火锅食材 B2B 平台 UI / UX 设计规范

> 适用范围：微信小程序、网页客户端、网页管理端、公司官网宣传页、统一组件库。
>
> 设计目标：建立一套带有苹果味的高级、极简、克制、具有质感的视觉系统，同时兼顾 B2B 业务场景下的信息效率、操作效率与品牌一致性。

---

## 1. 设计总纲

### 1.1 核心气质

本项目 UI 风格应同时满足以下特征：

- 苹果味的高级感
- 极简
- 克制
- 留白充足
- 质感强
- 视觉秩序清晰
- 适合商业系统长期使用
- 适合 B2B 场景的信息密度

### 1.2 关键词

- Elegant
- Calm
- Precise
- Minimal
- Premium
- Trustworthy
- Structured
- Commercial

### 1.3 设计原则

1. 不为炫技而设计动效
2. 所有视觉表达都服务于信息层级和操作效率
3. 官网要有品牌气质，管理端要有效率，小程序要易下单
4. 统一设计语言，统一交互反馈，统一组件状态
5. 视觉高级感来自比例、留白、字体、层次和微交互，而不是重装饰

---

## 2. 设计系统架构

建议采用“设计令牌 + 组件规范 + 页面模板 + 动效规则”的完整体系。

### 2.1 设计系统构成

- Design Tokens：颜色、字体、间距、圆角、阴影、动效时长
- Components：按钮、卡片、表单、标签、弹窗、列表、导航
- Patterns：首页、列表页、详情页、提交页、管理端表格页、官网 Hero 区
- Motion System：过渡、加载、反馈、强调、悬停

### 2.2 设计层级

- 基础层：颜色、字号、间距、阴影、动效
- 组件层：按钮、输入框、卡片、标签、导航
- 模式层：页面布局、模块组合、业务流程
- 品牌层：官网视觉气质与整体调性

---

## 3. 视觉风格定义

### 3.1 整体风格

建议主视觉参考 Apple 官网和系统设计语言：

- 深色与浅色对比明确
- 大面积留白
- 玻璃感、金属感、柔和阴影少量点缀
- 高级灰为基底，强调色少而精
- 元素排列有严格对齐和秩序感

### 3.2 色彩基调

推荐采用中性深色为主、浅色为辅的双主题策略。

#### 深色模式主基调

- 背景：近黑、深灰、石墨灰
- 文本：冷白、浅灰
- 强调色：可控制在 1 个主强调色 + 1 个辅助强调色
- 状态色：成功、警告、错误、信息明确区分

#### 浅色模式主基调

- 背景：暖白、雾白、极浅灰
- 文本：深灰、接近黑色
- 卡片：白色/微灰卡片，轻阴影
- 强调色：克制使用

### 3.3 主色建议

可采用以下思路：

- 主色：冷调蓝灰或深蓝黑系
- 辅色：银灰、雾灰、石墨灰
- 强调色：少量高饱和蓝、金属银、冷绿中的一种
- 危险色：用于错误、库存告警、下单失败

### 3.4 禁止的视觉风格

- 大面积彩虹渐变
- 过度拟物
- 花哨阴影
- 过多描边和高对比噪音
- 信息堆砌但缺少层级
- 无意义装饰图形

---

## 4. 设计令牌规范

### 4.1 字体

建议统一系统无衬线字体策略：

- iOS / macOS：SF Pro 风格优先
- Windows：系统无衬线字体优先
- Web：以现代无衬线字体为主

#### 字体原则

- 标题强调字重和字距
- 正文清晰易读
- 管理端避免过度纤细字体
- 官网可适当放大标题，增强品牌感

### 4.2 字号层级

建议建立严格的字号梯度：

- Display：用于官网主视觉大标题
- H1 / H2 / H3：页面标题与模块标题
- Body：正文和常规文本
- Caption：辅助说明
- Micro：标签、时间、辅助信息

### 4.3 间距系统

建议采用 4 或 8 的倍数系统：

- 4px：最小间距单位
- 8px：组件基础间距
- 12px / 16px / 24px / 32px / 48px：常用空间

### 4.4 圆角系统

- 小控件：轻微圆角
- 卡片：中等圆角
- 大模块：更柔和的圆角
- 整体风格以克制为前提，不要过度圆润

### 4.5 阴影与层次

- 轻阴影优先
- 多用层级、透明度、背景变化表达深度
- 不要使用厚重投影
- 高级感来自“轻”，不是“重”

---

## 5. 主题策略

### 5.1 推荐方案

采用“双主题 + 默认深色/浅色可切换”策略。

#### 业务建议

- 官网：浅色或双主题均可
- 小程序：浅色优先，局部深色强调
- 管理端：深色优先，提升视觉高级感和专注度
- 客户端：浅色为主，增强商品浏览舒适度

### 5.2 主题切换规则

- 切换必须平滑
- 主题变量统一由设计令牌控制
- 主题切换只改变视觉，不改变信息结构

---

## 6. 组件设计规范

### 6.1 按钮

#### 按钮层级

- Primary：主动作，如提交订单、保存、确认
- Secondary：次动作，如返回、次级筛选
- Ghost：轻量动作
- Danger：删除、作废、取消

#### 按钮风格

- 轮廓清晰
- 文案简短
- 状态明确
- 禁用态明显
- 点击反馈柔和快速

### 6.2 卡片

卡片是本项目最重要的基础视觉容器。

#### 卡片规则

- 适度圆角
- 轻边界或轻阴影
- 内容层次分明
- 不要让卡片内部过于拥挤

#### 适用场景

- 商品卡片
- 客户卡片
- 订单卡片
- 统计卡片
- 官网内容模块

### 6.3 表单

#### 表单规则

- 标签、输入、提示、错误信息层级明确
- 必填项标记统一
- 表单分组清晰
- 复杂表单分步骤完成

#### 管理端要求

- 长表单可分区块
- 高风险操作需二次确认
- 敏感字段需提示后果

### 6.4 标签与状态徽标

- 用于价格、库存、订单状态、客户等级、审批状态
- 标签颜色必须有明确语义
- 不要为了好看而滥用颜色

### 6.5 列表与表格

#### 客户端列表

- 图文结合
- 使用卡片或列表块
- 重点信息突出

#### 管理端表格

- 强调密度和效率
- 固定表头、筛选、分页、批量操作
- 表格行间距适中，避免过于松散

## 8. 动效规范

本项目允许动效，但必须“克制、品牌化、服务体验”。

### 8.1 动效原则

1. 动效必须有功能意义
2. 动效时长短，反馈快
3. 不影响操作效率
4. 不可喧宾夺主
5. 所有动效必须统一节奏

### 8.2 推荐动效类型

#### 页面切换

- 路由进入与退出使用轻微渐变/位移
- 避免大幅飞入飞出
- 页面切换要像“系统级过渡”而不是“娱乐动画”

#### 微交互

- 按钮点击轻微缩放或压感反馈
- 卡片悬浮轻微抬升
- 图标状态变化使用柔和过渡

#### 骨架屏

- 数据加载时必须有骨架屏
- 小程序和 Web 均要统一加载体验

#### 悬浮与层次

- 鼠标悬浮时轻微抬升
- 阴影/边界/位移变化要轻

#### 数字动效

- 统计数字可平滑递增
- 适合管理端首页指标

### 8.3 动效时长建议

- 快速反馈：120ms - 180ms
- 常规过渡：180ms - 260ms
- 模态切换：240ms - 320ms

### 8.4 禁止的动效

- 大面积弹跳
- 夸张旋转
- 过长加载动画
- 影响阅读的闪烁效果
- 过度装饰性的视差导致信息不清晰

## 9. 响应式与终端适配

### 9.1 微信小程序

- 单列布局为主
- 底部导航简洁清晰
- 触控区域足够大
- 重要按钮应适合单手操作

### 9.2 网页客户端

- 支持中等屏幕与大屏幕
- 商品信息可适度多列展示
- 下单流程保持简洁

### 9.3 管理端

- 适合桌面端
- 信息密度更高
- 筛选区、表格区、详情区要结构明确
- 可考虑左右分栏布局

### 9.4 官网

- 移动端优先可访问
- 桌面端强调品牌视觉和留资效率

## 11. B2B 业务视觉重点

本项目不是消费级电商，而是 B2B 食材业务，因此 UI 必须突出以下能力：

- 工厂直供
- 价格可信
- 订单清晰
- 库存透明
- 履约可靠
- 品牌专业

### 11.1 商品展示重点

- 清楚显示规格
- 显示客户专属价提示
- 显示库存/预警状态
- 显示“快速复购”入口

### 11.2 订单展示重点

- 订单状态清晰
- 金额与对账信息明确
- 支持快速查询历史订单

### 11.3 官网转化重点

- 强调工厂直供优势
- 强调平台可管理多品牌
- 强调高效下单与稳定履约
- 强调企业合作可信度

所有核心组件必须定义以下状态：

- default
- hover
- active
- focus
- disabled
- loading
- success
- warning
- error

- 点击后有即时反馈
- 加载有明确状态

### 13.1 图标风格

- 线性图标优先
- 图标风格统一
- 线宽一致
- 不使用过于卡通的视觉语言

### 13.2 插图使用

- 仅用于官网或空状态
- 管理端少用大插图
- 插图风格保持克制

## 14. 内容与文案规范

### 14.1 文案原则

- 简短
- 明确
- 专业
- 不夸张
- 避免口号堆砌

### 14.2 标题规则

- 首页标题要有品牌感
- 详情页标题要有商品识别性
- 管理端标题要准确表达业务动作

## 15. 设计与开发协作规范

### 15.1 设计交付物

这套 UI 应该是：

- 像 Apple 一样克制
- 像商业系统一样高效

## 19. UI 页面模板规范

本章节定义项目最核心的页面模板，作为小程序、网页端、管理端的统一页面骨架。所有实际页面在实现时，都应优先遵循这些模板，再根据业务做局部扩展。

### 19.1 页面模板总原则

1. 页面结构先于视觉细节
2. 统一顶部、主体、操作区、状态区的布局逻辑
3. B2B 场景优先保证效率和信息清晰度
4. 小程序优先单列、轻交互
5. 网页端优先更强的浏览和复购效率
6. 管理端优先高密度信息呈现
7. 页面内关键操作只保留一个主 CTA

### 19.2 首页模板

#### 适用端

- 微信小程序首页
- 网页客户端首页
- 官网首页
- 管理端首页

#### 模板结构

1. 顶部品牌区
   - Logo / 品牌名称
   - 简短品牌标语
   - 主题切换入口（可选）

2. 核心价值区
   - 一句话说明平台价值
   - 突出“工厂直供”“快速下单”“稳定履约”等关键信息

3. 快捷入口区
   - 快速下单
   - 商品分类
   - 订单查询
   - 常用功能

4. 内容推荐区
   - 推荐商品
   - 热销商品
   - 品牌推荐
   - 客户常购

5. 状态提示区
   - 库存预警
   - 待处理订单
   - 最新公告

6. 底部导航 / 快捷操作区
   - 小程序使用底部导航
   - 网页端使用侧边栏或顶栏导航

#### 首页设计要求

- 首屏必须传达业务定位
- 不要让首页只变成图标集合
- 不要把所有功能平铺到首屏
- 优先体现品牌气质和下单效率

### 19.3 商品列表页模板

#### 适用端

- 微信小程序
- 网页客户端
- 管理端商品列表

#### 模板结构

1. 顶部筛选区
   - 分类切换
   - 搜索框
   - 排序条件
   - 品牌/仓库筛选

2. 列表主体区
   - 商品卡片 / 列表项
   - 图片
   - 名称
   - 规格
   - 价格
   - 库存状态
   - 快速加购按钮

3. 分页或继续加载区
   - 下拉加载
   - 分页器
   - 加载状态

#### 商品列表页设计要求

- 商品名称必须一眼可识别
- 价格和库存必须优先显示
- 支持快速复购场景
- 小程序用卡片式列表，管理端用表格式或密度更高的列表

### 19.4 商品详情页模板

#### 适用端

- 微信小程序
- 网页客户端
- 官网产品页

#### 模板结构

1. 顶部主视觉区
   - 商品主图 / 轮播图
   - 商品标题
   - 核心卖点标签

2. 价格信息区
   - 基础售价
   - 客户专属价提示
   - 阶梯价提示
   - 库存提示

3. 规格说明区
   - 规格参数
   - 包装方式
   - 单位
   - 保存建议

4. 购买操作区
   - 数量加减
   - 加入购物车
   - 立即下单

5. 详情说明区
   - 产品介绍
   - 品牌/工厂信息
   - 适用场景
   - 物流/配送说明

6. 推荐关联区
   - 相似商品
   - 搭配购买
   - 同品牌推荐

#### 商品详情页设计要求

- 主图要干净，避免杂乱背景
- 价格区块必须突出
- 购买按钮要有明确视觉层级
- 工厂直供优势可在详情页体现

### 19.5 下单页模板

#### 适用端

- 微信小程序
- 网页客户端

#### 模板结构

1. 收货信息区
   - 收货人
   - 手机号
   - 地址
   - 配送方式

2. 商品清单区
   - 商品名称
   - 数量
   - 单价
   - 小计
   - 编辑入口

3. 价格汇总区
   - 商品总额
   - 优惠金额
   - 调价金额
   - 应付金额

4. 备注与说明区
   - 订单备注
   - 配送要求
   - 特殊说明

5. 提交操作区
   - 提交订单主按钮
   - 返回修改次按钮

#### 下单页设计要求

- 页面必须把“金额结果”放在清晰区域
- 提交按钮固定在易点击位置
- 下单步骤尽量短，不要让用户迷路
- 支持人工调价提示，但不能让流程混乱

### 19.6 订单页模板

#### 适用端

- 微信小程序
- 网页客户端
- 管理端订单详情页

#### 模板结构

1. 订单状态区
   - 当前状态
   - 时间线
   - 关键节点

2. 订单信息区
   - 订单号
   - 下单时间
   - 客户信息
   - 配送信息

3. 商品明细区
   - 商品列表
   - 数量
   - 单价
   - 小计

4. 金额汇总区
   - 合计金额
   - 调价金额
   - 应付金额
   - 已支付 / 待支付

5. 操作区
   - 取消订单
   - 再次购买
   - 确认收货
   - 进入售后 / 联系客服

#### 订单页设计要求

- 状态必须一眼明确
- 时间线适合展示履约进度
- 再次购买是重要行为，必须显眼
- 管理端可增加审批、改价、发货等后台操作入口

### 19.7 管理端首页模板

#### 适用端

- 网页管理端

#### 模板结构

1. 顶部概览区
   - 今日订单数
   - 今日销售额
   - 待处理订单
   - 库存预警数

2. 趋势图表区
   - 订单趋势
   - 销售趋势
   - 热门商品趋势

3. 待办事项区
   - 待确认订单
   - 待发货订单
   - 待处理售后
   - 库存不足商品

4. 快捷操作区
   - 新增商品
   - 新建客户
   - 创建订单
   - 调整库存

5. 列表区
   - 最新订单
   - 最近操作记录
   - 审计日志

#### 管理端首页设计要求

- 风格要像苹果官网一样克制和高级
- 指标卡片必须整齐一致
- 图表要少而精，不要堆砌
- 留白要充分，但不能浪费屏幕空间

### 19.8 列表页模板

#### 适用端

- 管理端客户列表
- 管理端商品列表
- 管理端订单列表

   - 分页器

#### 列表页设计要求

- 管理端优先表格化
- 客户端优先卡片化
- 操作按钮不要过多
- 关键状态一定要可见

### 19.9 详情页模板

#### 适用端

- 客户详情
- 商品详情
- 订单详情

#### 模板结构

1. 主信息区
2. 状态区
3. 核心属性区
4. 操作区
5. 相关记录区

#### 详情页设计要求

- 不要把详情页做成长表单堆叠

### 19.10 表单页模板

#### 适用端

### 19.11 空状态与异常状态模板

#### 适用场景

本规范适用于本项目全部前端终端。下一步实际落地时，应先建立设计令牌和核心组件库，再依次覆盖小程序、网页客户端、管理端和官网页面。
